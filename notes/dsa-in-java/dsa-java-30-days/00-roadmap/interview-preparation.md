# Interview Preparation Guide

DSA is the **means**. The interview is the **end**. This guide bridges them.

---

## The Two Interview Rounds

| Round            | Duration   | Focus                          | Style                         |
|------------------|------------|--------------------------------|-------------------------------|
| Online coding    | 60–90 min  | 2–4 DSA problems               | Automated judge (HackerRank etc.) |
| Live coding      | 45–60 min  | 1–2 DSA problems + discussion  | Whiteboard / shared editor    |
| System design    | 45–60 min  | High-level design              | Conversational                |
| Behavioural      | 30–45 min  | Past experience                | STAR method                   |

This course covers **online coding** + **live coding DSA**. System design and behavioural are out of scope.

## Live Coding — Communication Template

When given a problem, follow this script:

> "Let me make sure I understand: we have [input], and we need to return [output]. Is that right?"

> "Some quick examples: if input is X, output should be Y. Edge case: empty input → ..."

> "I'll start with brute force: [explain]. That gives us O(n²) time."

> "To optimise, I notice [pattern]. I'll use [data structure / algorithm]."

> "Here's the code..."

> "Let me trace through with the example: ..."

> "What if the input is empty? My code returns [X]. Good."

## Timeboxing in Interviews

| Phase                | Minutes |
|----------------------|--------:|
| Understand + clarify |    5    |
| Examples + brute     |    5    |
| Brute code           |   10    |
| Optimise + code      |   15    |
| Test + refine        |    5    |
| Discuss trade-offs   |    5    |
| **Total**            |  **45** |

If brute is all you finish, that's still better than an unfinished optimal.

## Common Mistakes Candidates Make

- ❌ Jumping into code without clarifying.
- ❌ Silent coding.
- ❌ Not testing their own code.
- ❌ Over-engineering (writing a class hierarchy for a 20-line problem).
- ❌ Ignoring hints from the interviewer.
- ❌ Giving up after one failed approach.
- ❌ Forgetting edge cases (null, empty, single element).

## How to Use This Course for Interview Prep

1. **Days 1–11** → Learn the language & core techniques.
2. **Days 12–17** → Core data structures.
3. **Days 18–21** → Trees.
4. **Days 22–26** → Algorithm paradigms (greedy, backtracking, graphs).
5. **Days 27–29** → DP (the differentiator).
6. **Day 30** → Pattern recognition under pressure.

After Day 30:
- Re-solve the Top 30 list above.
- Time yourself.
- Do at least 3 mock interviews with a friend.
- Read the failure modes of each algorithm again.

## Behavioural Prep (the part people forget)

- Have 3 STAR stories ready: a hard bug, a conflict, a leadership moment.
- Know your top 3 projects cold.
- Be able to explain *why* you made technical choices.

DSA gets you in the door. Behavioural gets you the offer.
